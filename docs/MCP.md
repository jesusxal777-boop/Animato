# Animato MCP

Animato exposes the local animation engine through the Model Context Protocol (MCP).

## What it gives an AI agent

- `list_models` — discover uploaded OBJ/GLB/FBX files.
- `prepare_animation` — turn a natural-language animation request plus a model into an Animato-aware prompt.
- `run_animation_code` — execute the Blender Python generated by the calling AI in Animato's existing isolated runner.
- `remove_animation` — remove a named animation clip with the fixed Blender worker.
- `get_mcp_status` — inspect capabilities and whether code execution is enabled.

The design is intentionally agent-first: the AI host (GPT, Claude, Grok, Cursor, VS Code, or another MCP host) can generate the Blender code, while Animato supplies the model-aware context and local execution engine.

## Transports

The server supports standard MCP **stdio** for local clients and **Streamable HTTP** at `/mcp` when the FastAPI server is running. Streamable HTTP is the current transport to use for deployed MCP services; stdio is ideal when the host launches Animato as a local process.

## Local setup

Install dependencies:

```bash
uv sync
```

Run the MCP server directly over stdio:

```uv
uv run python -m app.mcp_server
```

For the MCP Inspector:

```bash
uv run mcp dev app/mcp_server.py
```

Or run the normal FastAPI server and use the mounted MCP endpoint:

```bash
uv run fastapi run main.py
```

MCP endpoint:

```
http://127.0.0.1:8000/mcp/
```

## Enabling animation execution

The underlying Animato runner executes Blender Python. For that reason, the MCP execution tool is **off by default**.

For a trusted local setup:

```bash
ANIMATO_MCP_ALLOW_CODE_EXECUTION=true uv run python -m app.mcp_server
```

Do not expose an execution-enabled MCP server directly to the public internet without adding authentication, authorization, rate limits, and a sandbox boundary appropriate for your deployment.

## Client compatibility

MCP is a protocol, so the server is not tied to one model provider. Any MCP host that supports the server's transport and negotiated protocol can discover the same tools and JSON schemas.

Typical configuration concepts are:

- **Local clients:** launch `python -m app.mcp_server` over stdio.
- **Remote clients:** connect to the Streamable HTTP URL ending in `/mcp/`.
- **Browser-hosted clients:** deploy behind HTTPS and configure MCP transport security and CORS for the exact trusted origins.

See the official MCP SDK documentation for transport and client details.
